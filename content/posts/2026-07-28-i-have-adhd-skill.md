# i-have-adhd：讓 AI 回答更容易開始、更容易完成的輸出 Skill

`i-have-adhd` 是一個讓 AI 輸出更有效率的 skill。

它不是單純叫 AI「講短一點」，而是把回答改成更容易行動的形狀：先告訴你下一步，少講支線，分清楚目前狀態，讓你不用在一大段文字裡自己找重點。

GitHub 連結：[https://github.com/ayghri/i-have-adhd](https://github.com/ayghri/i-have-adhd)

## 它解決什麼問題

有些回答看起來很完整，但很難開始做。

問題通常不是資訊不夠，而是資訊太散：

- 第一段在鋪陳背景，真正要做的事藏在後面
- 一個步驟裡塞了太多動作
- 上一輪做到哪裡，下一輪又要重新想
- 錯誤訊息講得很委婉，但沒有直接說原因和修法
- 最後用「有需要再告訴我」結尾，沒有下一個可做的小動作

`i-have-adhd` 的重點就是把這些摩擦拿掉。

## 核心規則

這個 skill 最重要的是五件事：

- 第一行就給下一步
- 多步驟任務用編號
- 每一輪都重述目前狀態
- 避免支線和順口補充
- 結尾只留一個兩分鐘內能做的動作

它也會要求回答給具體時間，例如「約 5 分鐘」比「等一下」更好。

## 實際差異

一般回答可能會長這樣：

```text
這個問題可以從幾個方向來看。首先我們需要理解目前的狀態，接著再判斷下一步要怎麼做。如果你願意，我可以幫你整理。
```

套用 `i-have-adhd` 之後，會比較像這樣：

```text
下一步：打開分類頁，確認導遊口說文章是否出現在列表。

1. 看分類頁有沒有文章標題
2. 點「閱讀」
3. 如果不能打開，把網址貼給我
```

差別不是變冷淡，而是變得更好執行。

## 我今天怎麼用它

我把它用在這個部落格整理流程裡。

例如新增導遊口說文章時，它會讓工作變成：

- 先說正在做哪一步
- 一次只處理一個明確目標
- 做完後直接給文章連結
- 不把所有可能改進都塞到同一段
- 結尾只留下一個下一步

這很適合內容整理、考試備考、網站修改和任何容易中途分心的工作。

## 適合什麼情境

我會在這些情境開啟它：

- 要整理大量考試資料
- 要把文章拆成可執行步驟
- 要 debug 網站問題
- 要連續修改 UI
- 要避免每次都被一大段說明淹沒

如果是單純聊天、發想風格、寫比較有情緒的文章，可能不一定要開。

## 快速使用方式

如果要啟用，可以說：

```text
使用 i-have-adhd
```

如果要關掉，可以說：

```text
stop adhd mode
```

## 我的結論

`i-have-adhd` 對我來說像是一個「行動導向濾鏡」。

它不會替你做決定，但會讓每一輪對話都更清楚：現在在哪裡、下一步是什麼、剛剛完成了什麼。

這對個人知識管理很有用，因為整理資料最難的地方，常常不是理解，而是開始、接續和收尾。
